## Performance findings

`app/page.tsx` already lazy-loads data by active section and performs independent reads in parallel. Remaining risks:

1. A single server component coordinates many unrelated datasets and sends broad `select("*")` queries.
2. Overview still loads several modules simultaneously.
3. No measured Web Vitals, query timings or bundle budget is committed.
4. Some client panels mutate Supabase directly, increasing duplicated authorization/error-handling paths.
5. No pagination is visible for large employee/inventory lists.

Optimization without production traces would be guessing. Add observability first, then split page queries, select explicit columns and paginate.
